# LumenCode 0.1.0

Structural code exploration for Linux, macOS and Windows, using the same shared
C++/Tree-sitter analysis engine.

## Downloads

| Platform | Package | Installation |
| --- | --- | --- |
| Linux x86_64 | `LumenCode-Linux-x86_64-0.1.0.flatpak` | Install with Flatpak, or use the website's repository install link for updates. |
| macOS Intel and Apple Silicon | `LumenCode-macOS-universal-0.1.0.zip` | Extract and drag LumenCode to Applications. Developer ID signed and notarized. |
| Windows x64 | `LumenCode-Windows-x64-0.1.0.zip` | Extract the entire ZIP and run `LumenCode.Windows.exe`. No installer. Unsigned. |

Matching copies are hosted independently in GitHub Releases and at
`https://lumencode.app/downloads/v0.1.0/`. `SHA256SUMS` contains the archive hashes;
`release-manifest.json` records package provenance and signing status. The Linux
Flatpak repository continues serving updates at its existing address.

Linux requires a working Flatpak installation and the KDE 5.15/25.08 runtime.
The macOS application and every bundled library contain both architectures and
target macOS 14. Windows requires Windows 10 version 2004 or later, on x64.

The Windows package is unsigned. SmartScreen may show a warning; where the
option is available, choose More info, then Run anyway if you trust the download.
Smart App Control and workplace policies can block unsigned applications.

## Validation and limits

- The shared language/recovery fixtures cover 104 cases / 638 assertions.
- macOS native and Intel/Rosetta engines match complete analysis results for all
  6,297 pinned regular corpus files. macOS signing, notarization, ticket stapling
  and Gatekeeper checks pass, including fresh ZIP extraction and both launches.
- The Windows ZIP is checked after fresh extraction on the development VM,
  including file hashes and GUI startup/behaviour without developer discovery
  paths. This does not establish clean-machine or SmartScreen acceptance.
- The signed Linux Flatpak passes all shared fixtures in its Platform runtime.
- Physical Intel hardware, a macOS 14 launch and broader clean-machine testing
  remain follow-ups. macOS 14 support is based on build/dependency metadata and
  relocation checks, not an actual macOS 14 test.

All platform packages use the accepted shared analysis sources. Their build
revisions differ because macOS notarization and Linux signing completed before
release assembly. The manifest records those revisions rather than claiming
all archives were rebuilt from the release tag. Platform source comparisons
ensure the included application/engine sources match the release tree.

The public release uses version 0.1.0. macOS keeps its existing notarized build
20261018. Its signed bundle must remain unchanged when copying or hosting it.
